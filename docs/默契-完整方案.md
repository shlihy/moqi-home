## 0. 背景（Context）

原方案是一个"感知—汇聚—决策—执行"的闭环：米家传感器 + 树莓派 5 + OpenAI Assistants API 每 60 秒推理一次，输出 JSON 节能策略，经白名单/钳制校验后通过 python-miio 与 GPIO 下发。

项目目标已经变了：**核心是做一个能学会家人习惯、主动适应、与人形成协作关系的家居智能体；节能是验证指标**。系统真的学会了"按需供给"，能耗就应当在舒适度不降的前提下自然下降，这个下降就是"它真学到了东西"的证据。

与米家的根本区别：
- 米家：**用户配置规则 → 系统执行**
- 本项目：**系统观察行为 → 用户确认（或纠正）理解**。规则从行为里长出来，用户从不"编写"规则。

已确认的约束：
- 时间：距提交 2–4 个月（约 2026 年 12 月—2027 年 1 月）
- 场地：未定。可用的有两户：同伴家（米家全屋）、姜文山家（中央空调 + 新风，墙面板控制的整套系统）
- 预算：1 万元人民币
- 硬件：树莓派尚未购买（问题是选 4GB 还是 8GB，答案见 §10.1）

**一句话概括新方案：系统观察人怎么用这个家，自己形成理解，有把握时替人去做；人用手一改，它就明白了。节能是"学对了"的副产品，也是证据。**

### 新旧方案对照

| 维度 | 原方案 | 新方案「默契」 |
|---|---|---|
| 决策位置 | 云端 LLM，每 60 秒一次 | 本地三速闭环：反射(<0.5 s) / 习惯(事件触发) / 反思(每晚) |
| 记忆 | 无，每次推理都是无状态 prompt | 四层记忆 + 未解决问题清单 + 夜间"梦境整理" |
| 学习信号 | 无，偏好写在提示词里 | 人的物理操作，其中**撤销和修正**是最重要的信号 |
| 行为归因 | 无，分不清是人改的还是系统改的 | 归因器：每次状态变化都标注 人 / 智能体 / 设备自身 |
| 自主程度 | 所有决策一视同仁 | 每条习惯单独有**信任等级**，靠被接受一步步升级 |
| 安全 | 白名单 + 数值钳制（只管语法） | 独立的确定性安全内核（管语义、时序、物理保护、人类租约） |
| LLM 角色 | 司机：直接出控制指令 | 科学家：只提假设，由数据裁决，永远碰不到设备 |
| 交互 | 无 | 物理为主，语音为辅，App 只做管理 |
| 实验 | 无基线、无对照、无舒适度指标 | 随机日交叉设计 + 天气归一 + 离线回放基准 + 预注册 |
| 软件栈 | bluepy / python-miio / Assistants API | Home Assistant + 自研 Python 智能体 + sherpa-onnx + EdgeJev |

## 1. 原方案诊断：为什么必须重写

1. **核心依赖已经失效。** OpenAI Assistants API 已于 **2026-08-26 正式下线**，现在所有调用都会报错。另外，国内本来就无法稳定直连 OpenAI。
2. **决策在云端，60 秒一次。** 断网就瘫痪，每次延迟好几秒，隐私数据要出户，成本随使用时间线性增长。具身系统里，"开窗就停空调"这种反射不能去等云端。
3. **没有记忆，就不可能学习。** "用户作息模式"只存在于提示词里。系统不会随时间变好，也拿不出任何东西证明它学到了什么。
4. **看不见人的手（最隐蔽，也最致命）。** 系统分不清一次状态变化是自己造成的还是人造成的。可人纠正系统的那一下，恰恰是最有价值的学习信号。原方案把所有数据都倒进同一个"状态缓冲区"，归因信息就丢了。
5. **安全校验只管语法，不管语义。** 白名单加钳制能拦住"35°C"，拦不住"凌晨 2 点开卧室灯"、"10 分钟内开关压缩机 6 次"、"开着窗制热"。
6. **实验无法证伪。** 没有基线期，没有天气归一化，没有舒适度指标，没有对照组，"有效压降能耗"这句话没法检验。
7. **技术栈已经老化。** bluepy 多年无人维护，python-miio 基本停更。小米官方的 Home Assistant 集成（ha_xiaomi_home）和 HA 自带的 Xiaomi BLE 集成已经覆盖了原方案的采集与控制。
8. **新颖性已被追平。** 小米 2026 年 6 月开源了 **Miloco 2.0**（MiMo 大模型 + 家庭记忆 + 摄像头识人 + 习惯自动化），"米家 + 大模型"不再是差异点，我们必须在别的维度上超越（见 §14）。

## 2. 设计原则：具身约束是一等公民

| # | 原则 | 含义 |
|---|---|---|
| P1 | 反射在本地，理解在夜里，云只是可选的反思 | 断网时除"写日记"以外的一切照常运行 |
| P2 | 人永远赢 | 人的物理操作立即生效，并给该设备一段"人类租约"，租约期内智能体不得再改 |
| P3 | 行为就是标签 | 不问"要不要设为习惯"，人的操作和撤销本身就是回答 |
| P4 | 先做后说，说了能改 | 第一次替人做某件事时说一句，并告诉对方怎么撤销：用手改回来就行 |
| P5 | 自主是挣来的 | 每条习惯有独立的信任等级，被接受就升级，被撤销就降级 |
| P6 | LLM 当科学家，不当司机 | 大模型只能提出候选假设，进入影子模式由数据裁决，永远不能直接控制设备 |
| P7 | 系统不在关键路径上 | 拔掉树莓派，家里一切照常：面板、开关、米家 App 都能用 |
| P8 | 系统自身耗电计入账本 | 净节能 = 节省量 − 系统自身功耗（树莓派约 5 W，每天约 0.12 kWh） |

## 4. 感知与可观测性：先让系统看见人的手

### 4.1 归因器：整个学习机制的地基
- **指令账本**：智能体发出的每条指令都记录（设备、属性、目标值、发送时间）。
- **回声匹配**：状态变化如果在回声窗口内（快设备 5 s，慢设备 30 s）与账本里的某条指令匹配，就标为 `agent`，否则标为 `human`。
- **HA context 辅助**：Home Assistant 的状态事件自带 context，可以区分服务调用触发的变化和外部变化（物理开关、面板、米家 App）。
- **设备自身行为**（空调自动模式、定时器）标为 `device`。第 1 周要**盘点并关闭或登记米家 App 里已有的自动化**，否则它们会被误判成"人的习惯"。

### 4.2 双向可观测清单
每个受控设备必须同时满足两条：**(a) 状态可读；(b) 人手操作会反映到可读状态上。** 不满足的设备只能观测，不能自动化。

| 设备 | 接入方式 | 能看见人手吗 |
|---|---|---|
| 米家灯 / 墙壁开关 / 插座 | ha_xiaomi_home（配中枢网关可本地控制） | 能 |
| 米家温湿度计（LYWSD03MMC） | HA 自带 Xiaomi BLE 集成（代替 bluepy） | 纯传感器 |
| 中央空调 / 新风墙面板 | 见 4.3 决策树 | 取决于协议，**第 2 周末前必须确认** |
| 窗户 | 门窗传感器 | 能 |
| 红外遥控的分体空调（备用） | **ESP32 + 红外接收头（约 30 元）嗅探遥控器**。空调遥控器每按一次都会发送完整状态帧，IRremoteESP8266 能解码 65 种空调协议 | 能（这是个便宜又巧的办法） |

### 4.3 中央空调接入决策树（第 1 周任务）
先拍下墙面板、室内机和室外机的铭牌，再按下面的顺序判断：
1. 面板属于某个智能家居品牌（Aqara / 欧瑞博 / 涂鸦 / HDL / KNX 等）→ 用 HA 的对应集成或 Matter 接入。
2. 是多联机（大金 / 日立 / 美的 / 格力 / 海信等）→ 查是否已装或能加装 Modbus 网关、品牌 WiFi 模块 → 走 USB-RS485 + HA Modbus 集成。
3. 完全封闭，只能用厂商 App → 走只读方案：电能计量推断开停 + 室温。这一户降级为"观测 + 能耗"站点，执行实验以米家站点为主。

**关卡：第 2 周末必须能读到"面板上的手动修改"，否则启用方案 3。**

### 4.4 传感器布置（每户）
- 每个主要房间：毫米波人在传感器 + 温湿度计（+ 门窗传感器）
- 客厅：CO₂ 检测仪。它既是舒适度指标，也是新风节能的抓手
- 室外温度：Open-Meteo 免费 API（用于天气归一化）
- 电能计量：空调回路装导轨式计量电表 + CT，**必须请电工安装，学生不碰 220 V 配电箱**；小电器用计量插座；全屋日用电量从"网上国网"App 读取（免费、权威的第三路数据）

## 5. 记忆系统：四层 + 一张问题清单

### 5.1 分层

| 层 | 内容 | 存储 | 保留 | 例子 |
|---|---|---|---|---|
| L0 事件流 | 带归因标签的原始事件 + 传感器读数 | SQLite（WAL） | 原始 30 天，降采样后永久 | `19:13 客厅灯 off→on source=human` |
| L1 情节 | 以到家 / 离开 / 入睡 / 起床等转折点切分的片段 | SQLite | 永久 | "10/14 周二 19:12 到家 → 开客厅灯(人) → 19:20 面板调到 24°C(人)" |
| L2 习惯线索 | 结构化的 槽位 × 情境 → 证据(α, β)、信任等级、风险等级、状态 | SQLite | 按遗忘规则 | "工作日 23:00–23:30 · 客厅有人 → 关客厅灯：α=10.2, β=1.4, L2" |
| L3 理解 | 人能读、也能改的 Markdown + YAML，用 git 做版本管理 | 文件 + git | 永久，可回滚 | `rooms/客厅.md`、`routines/工作日晚间.md` |
| 问题清单 | 借鉴"衔枝"的未解决问题：观察到了但解释不了的现象 | Markdown | 解决后归档 | "周二、周四 22:00 空调提前关，原因未知（已观察 4 次）" |

**git 作为记忆的版本控制**：每晚一次提交，比如"10/21 梦境整理：+2 习惯，−1 习惯，1 个新问题"。App 里能看到"今天学到了什么、忘了什么、改了什么"，出错能一键回滚。可审计的学习本身就是论文亮点。

### 5.2 遗忘：情境暴露式遗忘 + 季节休眠（本方案原创点之一）
- 常见做法（Ombre Brain、kiwi-mem）是**按时间衰减**热度。问题在于一个冬天过去，夏天的空调习惯就忘光了。
- 本方案：**情境 k 再次出现时，才对它的旧证据做衰减**，即 α, β ← γ·α, γ·β（γ≈0.9），再加上今天的新证据。情境不出现，证据就不衰减。
- 效果：
  - 作息变了 → 几次暴露后，新证据自然覆盖旧证据（快速适应）
  - 季节变了 → 夏季情境不再出现，习惯进入**休眠**而不是被遗忘，明年升温时自动苏醒
- **矛盾检测**：近期接受率与长期接受率差异显著时，标记为"漂移"，分裂出新版本（比如入睡时间推迟了 30 分钟），旧版本休眠，不删除。

### 5.3 梦境整理（每晚 03:00，核心步骤不调用 LLM）
1. 把当天的 L0 事件切分成 L1 情节
2. 用情境暴露式遗忘更新所有 L2 证据
3. 挖掘新候选：14 天内同一（情境, 动作）出现 ≥4 次 → 以 L1 影子状态进入习惯库
4. 对照影子预测和人实际做了什么 → 更新每条习惯的命中率 → 升级或降级（见 6.5）
5. 矛盾检测、漂移分裂
6. 更新问题清单：新增无法解释的现象；尝试用新特征（星期几、天气）解释旧问题，解释得通就归档
7. 重新拟合房间热模型和到家时间分布（见 6.4）
8. 生成 L3 Markdown，做 git 提交
9. （可选，需联网）把**去标识化的周摘要**发给云端 LLM，让它写一段叙述性"理解"，并以**类型化提案**的形式提出假设（例如"建议加入'22:00 以后'这个情境切分"）。提案只能进入影子模式，是否采纳由数据裁决

> 为什么不用向量数据库 / RAG 做核心：家居记忆本质上是结构化的"时间—情境—动作"，瓶颈不在相似度检索。sqlite-vec 只在语音问答需要检索 L3 笔记时可选使用。

## 6. 学习机制：节能从"学对了"里自然长出来

### 6.1 学习信号分级

| 信号 | 定义 | 对模型的作用 |
|---|---|---|
| 自发操作 | 智能体没动，人主动操作 | 正样本（α +1） |
| **撤销** | 智能体执行后 10 分钟内人改回 | 强负样本（β +3），信任降级，启动人类租约 |
| **修正** | 执行后人朝某个方向微调（如 22→23°C） | 不算"错"，是偏好位移：更新该情境的设定温度分布 |
| 默认接受 | 执行后无人改动 | 弱正样本（α +0.5） |
| 语音 / App 明确表述 | "以后晚上别自动关灯" | 最高置信，写入 L3 成为约束 |

### 6.2 情境习惯模型（主力）
- 槽位 = （设备, 目标状态），例如（客厅灯, 关）、（卧室空调, 制热 22°C）。
- 情境特征：30 分钟时段、工作日 / 周末 / 假日、各房间有人与否、到家后经过的时长、室内外温度档、照度档、其他设备状态、手机是否在家（HA 手机 App 免费提供）。
- 模型：**分层贝叶斯计数 + 回退**。细情境数据不够时回退到粗情境（比如"周二 23:00"→"工作日 23:00"→"23:00"），输出 P(人会在接下来 15 分钟内做这个动作)。
- 选它的理由：小数据下也能工作，天然给出概率，**可解释**，能直接生成"过去 3 周工作日这个时间，你 11 次里有 10 次关了灯"这样的解释。
- 对照：LightGBM（同样的特征），作为 §11.3 离线基准中的一组。

### 6.3 在舒适边界上节能（设定温度）
- 每一次手动调面板，都是一个"这个情境下我想要多少度"的**显露偏好**样本，系统据此累积每个情境的设定温度分布。
- 智能体取分布中偏节能一侧的分位数：制热取约 35% 分位，制冷取约 65% 分位。**它只在你已经接受过的范围里节能。**
- 人往回调，分布就移动。最后节能量恰好等于你真实能容忍的程度，这正是"按需供给"。

### 6.4 世界模型：房间热模型 + 到家预测 → 准时预热
- 房间热模型（1R1C 灰箱）：dT/dt = (T室外 − T)/τ + k·u(t)，每晚用最小二乘从数据里拟合 τ 和 k。
- 到家时间分布：从门窗传感器、人在传感器、手机在家状态学出每个工作日的到家时间分布。
- 在"预测到家时间的 20% 分位 − 升到偏好温度所需时间"这一刻开始预热。**相比整天开着或到家才开，这是一个可量化的节能来源。**
- 离开判定超时也是学出来的：统计"离开多久算真的走了"，在"刚关就回来"的打扰代价和"空房间开着"的浪费之间取最优。

### 6.5 信任阶梯：用"挣来的自主"代替"问用户"

| 等级 | 名称 | 行为 |
|---|---|---|
| L0 | 观察 | 只记录 |
| L1 | 影子 | 预测但不执行，每晚对照人的实际行为统计命中率 |
| L2 | 执行 + 播报 | 执行；该习惯**第一次**执行时用语音说一句（见 8.2） |
| L3 | 静默执行 | 执行，不再说话 |

- 升级：用 Beta 后验。影子命中率满足 P(命中率 > 0.85) > 0.8 时升到 L2；接受率满足 P(接受率 > 0.9) > 0.8 时升到 L3。
- 降级：一次撤销从 L3 降到 L2；7 天内 2 次撤销退回 L1。
- 风险分级决定门槛，也决定能升到哪一级：

| 风险 | 例子 | 执行门槛 P | 最高等级 |
|---|---|---|---|
| 低 | 调灯、调新风风速 | 0.70 | L3 |
| 中 | 空调设定温度 ±2°C 以内 | 0.85 | L3 |
| 高 | 关空调、切换模式、夜间动作 | 0.95 | L2（永远播报） |
| 禁止 | 门锁、燃气、冰箱、路由器、医疗设备 | — | 永不自动 |

- 原理是期望效用：P·收益 > (1−P)·做错的代价。上表是它的简化版。**这取代了固定的"0.8 阈值"**，门槛由风险决定，自主由历史挣得。

## 7. 决策层选型：对 Jev / EdgeJev 思路的评估

### 7.1 你们提出的思路
本地运行 Jev 式类型化决策模型（EdgeJev，ONNX INT8，CPU 上约 15.6 ms），输入"传感器状态 + 云端 LLM 生成的自然语言习惯画像"，输出 Choice / Score / Noul 及置信度。≥0.8 执行，0.5–0.8 记录并等云端分析，<0.5 不做。云端 LLM 每天分析日志、更新画像、优化问题模板。

### 7.2 值得采纳的部分
- **输出类型化、有界**：只能从给定选项里选，不可能输出越界值或格式错误。本方案把它推广成原则：所有决策输出都必须是类型化提案。
- **带置信度的分流**：和信任阶梯的思想一致。
- **本地、毫秒级、支持中文**：EdgeJev 的 laya 后端（mmBERT-base，322M）支持中英文，Apache-2.0 协议。

### 7.3 用它做主控制器的风险
- **TypeSafe 官方列出的 Jev 弱点**包括：不能可靠地比较数值大小、日期排序不可靠、多跳推理差。而"现在 23:10、室温 21.5°C、比平时晚 20 分钟"恰恰需要这三样能力。
- **自然语言画像是有损压缩**：把"11 次里 10 次"这种统计证据写成一段文字再交给分类器读，次数和置信度就丢了。
- **校准不能迁移**：EdgeJev 的数字来自新闻分类和情绪数据集（laya INT8 在情绪集上只有 48.2%），在家居数据上的校准完全未知，0.8 这个阈值没有依据。
- **"0.5–0.8 等云端"等于不做**：云端每天分析一次，结果回来时那个时刻早就过去了。
- EdgeJev 目前**没有 ARM 基准**，需要在树莓派上实测。

### 7.4 本方案的分工

| 任务 | 用什么 | 理由 |
|---|---|---|
| 数值 / 时间 / 情境 → 是否执行 | 贝叶斯情境模型（LightGBM 作对照） | 直接从本家数据学，天然校准，可解释 |
| 语音 → 类型化纠正 | **EdgeJev laya INT8（本地）** + 规则兜底 | 语言理解正是它的强项，输出不会越界 |
| 解释"为什么这么做" | 证据模板（确定性）+ 可选 LLM 润色 | 解释基于真实计数，不会幻觉 |
| 夜间反思、提假设、写"理解" | 云端 LLM（DeepSeek / 通义千问，国内可用，3 个月约 100 元） | 只产出候选，进影子模式由数据裁决 |
| 生成语音解析用的问题模板 | 云端 LLM | 这是你们思路里"优化问题模板"的最佳落点 |

### 7.5 把分歧变成研究成果
在离线回放基准（§11.3）里，把 **"EdgeJev + 自然语言画像"** 设为正式对照组，与贝叶斯模型、LightGBM、云端 LLM、米家式静态规则放在同一份真实数据上比较。这样不管结果如何，Jev 思路都会成为论文里的一个**实验发现**，而不只是一个设计假设。

## 8. 交互设计

### 8.1 物理交互（主通道）：四个场景
- **A 撤销**：智能体 23:05 关了客厅灯，你 2 分钟内又打开。系统记为撤销，该习惯降级，并在 90 分钟内不再碰这盏灯（人类租约）。7 天内再撤销一次，就退回影子模式。
- **B 修正**：智能体按习惯把面板设到 22°C，你调到 23°C。系统不把这算作"错"，而是记为偏好位移，该情境的设定分布右移。
- **C 反射**：你开窗 1 分钟后，反射层停掉空调或调低新风。安全行为不需要学习。
- **D 习惯成形**：连续 5 个工作日 07:10 起床开卧室灯 → 影子预测开始连续命中 → 升到 L2。第一次执行时说："早，我把卧室灯开了。"以后就不再说。

### 8.2 语音（次通道）
- **硬件**：USB 全向会议麦克风扬声器，自带硬件回声消除，比麦克风阵列板省心得多。
- **链路**：sherpa-onnx 自定义中文唤醒词 → Silero VAD → SenseVoice-Small（本地，int8）→ 规则 + EdgeJev 类型化解析 → sherpa-onnx 中文 TTS。**音频不落盘，也不出户。**
- **三种用途**：
  - 解释："为什么把空调关了？"→"你出门 25 分钟了。过去 3 周工作日你都是 18 点以后才回来。今天要是早回来，我会提前 20 分钟开。"
  - 纠正："以后晚上别自动关客厅灯。"→ 解析为 intent=约束、device=客厅灯、长期=是（Noul 0.93）→ 写进 L3 约束，App 里可见
  - 闲聊式询问："你最近学到了什么？"→ 读当周的 git diff 摘要
- **说话预算**（体现"不唠叨"原则）：
  - 主动开口只限三种情况：新习惯第一次执行、安全事件、每天最多 2 次
  - 只在有人的房间说；23:00–07:00 静默；每次不超过 8 秒
  - **问题清单里的问题只在用户主动和它说话时顺带问一个**，每天最多 1 个。系统从不为了问问题而打扰人

### 8.3 App（第三通道）
- 直接用 Home Assistant 仪表盘 + 手机 HA App，**不自己开发 App**。手机 App 的在家状态还能顺便作为到家预测特征。
- 自定义面板"家的日记"：渲染 L3 Markdown、当天的 git diff、信任阶梯总览、问题清单。
- 管理开关：暂停学习 / 暂停执行 / "别碰"清单 / 回滚到某天的理解。

## 9. 安全与隐私

### 9.1 安全内核（独立进程，纯确定性，不含任何模型）
所有指令（包括来自 LLM 或语音的）都必须过这一关：

```yaml
living_ac:
  actions: [set_temperature, set_hvac_mode, turn_off]
  temperature: {heat: [18, 24], cool: [24, 28]}
  min_cycle_minutes: 10        # 压缩机保护：最短启停间隔
  max_actions_per_hour: 4
  human_lease_minutes: 90      # 人手操作后的租约
invariants:
  - 窗开 > 5 分钟 → 空调只允许 turn_off
  - 有人 且 CO₂ > 1200 ppm → 新风不允许调低
  - 23:00–07:00 → 不开灯、不说话
never_touch: [fridge, router, gas_*, lock_*, medical_*]
```

- 看门狗：智能体崩溃时保持现状，不回滚；HA 离线时什么都不做。
- 安全规则**只能在 App 里修改**，语音和 LLM 都无权改动。语音注入之类的攻击面因此被关在类型化解析之外。
- 物理总开关：拔电源。由于 P7，家里一切照常。

### 9.2 故障注入测试清单
断网、杀智能体进程、传感器没电、时钟跳变、重复或乱序事件、HA 重启、同时收到人手操作和智能体指令（竞态）。每一项都要写成可重复运行的测试。

### 9.3 隐私
- **不用摄像头**（与 Miloco 2.0 的根本区别之一）。
- 原始数据不出户，语音不落盘不出户。云端只收**去标识化的周摘要**：不含姓名和地址，时间粒度为 30 分钟。
- 原始事件保留 30 天，可随时查看和删除。
- **家庭成员知情同意书**：实验开始前全体成员签字，研究伦理写进论文。

## 11. 实验与验证设计

### 11.1 研究问题与假设
**研究问题**：只靠观察物理交互，家居智能体能否学会住户习惯、以可校准的自主度替人行动，从而在舒适度不下降的前提下降低能耗？

- **H1 学习**：习惯预测准确率随天数上升（学习曲线）
- **H2 协作**：每次执行的撤销率随时间下降，信任等级净上升
- **H3 节能**：执行日的能耗（按采暖度日归一）低于影子日，且舒适度**不劣于**影子日
- **H4 个性化**：同一套代码在两户学出**明显不同**的习惯。这能直接证明系统在学习，而不是在执行预设规则
- **H5 引擎比较**：在同一份数据上，贝叶斯情境模型的校准与准确率优于静态规则、EdgeJev+画像、纯 LLM

### 11.2 时间受限下的实验设计：随机日交叉
- 干预期内，**每两天为一块，随机指定为"执行块"或"影子块"**。影子块里系统照常学习和预测，但不执行。这样同时得到了对照组和离线准确率。
- 季节问题：上海 10–11 月是过渡季，空调负荷低。能耗的主要证据来自 **11 月下旬起的供暖期**，外加全年都有的照明、新风和待机。国庆期间的数据标为"假日"情境。
- **预注册**：干预开始前，把假设和分析方法提交到 git 仓库，用提交哈希作为时间戳。高中项目里做预注册的很少见，说服力很强。

### 11.3 离线回放基准（不占用现场时间）
在记录下的真实数据上，每 5 分钟以及每个事件发生时，让 5 个引擎分别预测"人接下来 15 分钟会做什么"，真值取归因为 `human` 的操作：
1. 米家式静态规则（团队开局一次性配置，例如"无人 15 分钟关灯"）
2. 贝叶斯情境模型（本方案）
3. LightGBM
4. EdgeJev laya + 自然语言画像（你们的思路）
5. 云端 LLM + 自然语言画像（抽样子集，控制成本）

指标：AUC-PR、Brier 分数 / ECE（校准）、提前量、学习曲线（准确率 vs 数据天数）。

### 11.4 指标总表

| 维度 | 指标 |
|---|---|
| 学习 | AUC-PR、Brier / ECE、影子命中率、各等级习惯数量随时间的变化 |
| 协作 | 撤销率（撤销次数 / 执行次数）、每日纠正次数趋势、人类租约触发次数 |
| 能耗 | 各回路日 kWh、全屋日 kWh（网上国网）、kWh / 采暖度日、净节能（扣除系统自身功耗） |
| 舒适 | 有人时处于偏好带内的时长占比、CO₂ < 1000 ppm 的时长占比、每周 5 题问卷（7 点量表，非劣效界值 0.5 分） |
| 系统 | 反射延迟（目标 <0.5 s）、可用率、断网存活、系统功耗 |

### 11.5 统计方法
- 日能耗 = β₀ + β₁·HDD + β₂·执行块 + β₃·周末 + ε，β₂ 就是效应量，用 bootstrap 给出 95% 置信区间。
- 如实报告：数据只有约 35 天，统计功效有限。**学习类指标（H1、H2）是主要证据，能耗（H3）是验证性证据。** 负面结果也要写进论文。

### 11.6 工程验证（系统能用的证据）
- 回放单测：用已记录的事件流驱动智能体，断言决策和安全内核的输出
- 延迟测试：从事件到指令的端到端时间
- 断网 24 小时测试：除 LLM 叙述外所有功能正常
- §9.2 故障注入清单全部通过

| 多人家庭无法区分是谁 | 高 | 以房间 / 家庭为单位建模；手机在家状态提供粗粒度身份；写入局限性 |
| 家人觉得被打扰或被冒犯 | 中 | 说话预算、静默时段、人类租约、一键暂停执行 |
| EdgeJev 在树莓派上太慢或中文效果差 | 中 | 回退到规则解析，EdgeJev 只进离线基准 |
| TF 卡或电源故障导致数据丢失 | 中 | NVMe SSD；每晚把 SQLite 和 git 备份到笔记本 |
| 电气安全 | 低，但后果严重 | 所有配电箱作业交给电工；学生只接低压设备 |

## 14. 与现有工作的差异和论文贡献

| | 米家自动化 | Miloco 2.0 | HA 自动化 | **默契** |
|---|---|---|---|---|
| 规则来源 | 用户编写 | 大模型 + 摄像头观察 | 用户编写 | 行为统计中长出 |
| 学习信号 | 无 | 视觉 + 对话 | 无 | **物理撤销与修正（带归因）** |
| 是否需要摄像头 | 否 | 是 | 否 | **否** |
| 自主度 | 固定 | 未公开 | 固定 | **按习惯挣得的信任阶梯** |
| 学习是否可验证 | — | 难 | — | **可审计（git 日记）+ 可量化（离线基准）** |
| 算力 / 功耗 | 云 | 电脑 + 云端大模型 API | 本地 | **树莓派约 5 W** |

**论文可主张的贡献**：
1. 以**行为归因**为基础、从物理交互中学习的家居智能体架构
2. **情境暴露式遗忘 + 季节休眠**的家居记忆机制
3. 用**风险加权的信任阶梯**取代"询问用户"的交互范式
4. **舒适边界节能**：节能量由学到的偏好分布自然决定
5. "LLM 当科学家不当司机"的分工，以及对 Jev 式类型化决策模型在家居场景的**实证评估**
6. 高中项目少见的实验严谨度：预注册、随机日交叉、天气归一、离线回放基准

**建议的新题目**：《从物理交互中学习：一个无摄像头、可审计的家居具身智能体及其节能验证》
