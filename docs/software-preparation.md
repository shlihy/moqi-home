# 软件准备与之后的 HA 接入

状态：2026-10-22，软件准备包与本地协议检查已完成。包内有源码、依赖、配置、模型配方、开发者 playground 和合成报告；真实模型、服务、音频和现场验收见[验收台账](jev-memory-acceptance.md)。

## 已确认的产品分工

代码能完成的判断优先使用代码；JEV 只解释剩余的受支持语义。DeepSeek 异步分析有依据的摘要，不参加日常动作的实时等待。首版按家庭／房间共用习惯，日常靠实际操作学习；需要表达时用语音，23:00–07:00 完全静默。

## HA 统一管理可控范围

源码 `custom_components/moqi/` 是待安装验证的 HA 自定义集成，不会在本轮连接现有 HA 或控制设备。之后安装到 HA 配置目录的 `custom_components/moqi/`，重启 HA，再在“设备与服务”添加 Moqi。

集成会在 HA 创建两个标签：

- **默契：允许观察**：给需要采集的实体贴上标签。
- **默契：允许控制**：给允许自动操作的实体贴上标签；这些实体同时允许观察。

在 HA 的**实体列表**选择；本版不继承整个设备或区域的标签，避免意外扩大范围。摄像头、图像、门锁等不进入该接口的支持范围。新增的 **Moqi automatic execution** 开关在初装时关闭；现场验收之前保持关闭。

实体标签是权限配置的来源，不要求用户再到 Moqi 网页维护一份名单。HA 的 Assist 暴露设置和普通 API 权限不同：此集成在专用执行入口同时检查所选实体、当前用户权限和最新配置版本。API token 仍是 HA 凭据，不因此成为通用的逐实体受限 token，不能提供给 DeepSeek 或 JEV。

协议端点：

| 接口 | 作用 |
|---|---|
| `GET /api/moqi/scope` | 当前可观察／可控实体、执行开关、名单版本 |
| `GET /api/moqi/profile` | 由 HA 实体标签、区域、设备类别和能力生成的采集/执行配置及待核实项 |
| `POST /api/moqi/execute` | 接收一个有 ID、时间和名单版本的有界动作；不接受任意服务名 |
| `GET /api/moqi/commands/{id}` | 查询持久化的派发状态 |

取消实体的控制标签后，新请求按最新名单拒绝；已经派发到物理设备的指令不能靠移除标签撤回。`service_completed` 只表示 HA 服务调用完成，不能冒充设备已经到位。POST 超时后先查回执，不自动重复执行。尚需在实际 HA 或隔离 HA 测试环境验证安装、并发撤权和持久化行为。

`python -m moqi.runtime --config config.local.json` 已接通 HA 配置读取、事件采集、自动学习、影子预测和回执处理，默认保持影子。示例实体不会作为现场名单使用。实体缺少区域、插座负载类别未核实、空调窗户信息未知时，会给出对应待核实项。普通 PIR 是 motion，不因为它的 OFF 推断房间无人；只有在 HA 明确标记“默契：可靠在场”的已核实信号才可作为持续在场来源。移房间或撤销观察会终止旧观测覆盖，保留历史；旧房间习惯不移植到新房间。

将来受控接入时，`--execute` 还需 HA 执行开关开启、设备在 HA 控制选择内、习惯已获得足够信任，以及独立安全进程复核通过。第一版执行范围按修订方案限于低风险灯具，其他设备继续学习/影子运行。执行前持久预留 ID；网络失败后只查同一 ID 的回执。匹配时间窗内的 HA 上下文及目标状态事件之后才记为 observed acknowledgment；设备集成是否提供真实回读仍属于现场验收。需要首次播报但合成/占用/预算条件不满足时不派发。

## DeepSeek 后台接口

配置示例为 `deploy/runtime.env.example`。密钥之后在部署环境填写，不发到聊天、配置 JSON 或 Git。

当前 `moqi.reflection` 发送过去七天的合格人类行为分组统计、去标识化的已有习惯和纠正计数，不发原始音频、语音原文、实体名称、房间名称或原始事件。它接受引用统计证据的 `context_split` 提案，以及保留固定答案域的 JEV 问题措辞候选，均不直接增加自主权。

开发者单次运行入口：

```sh
python -m moqi.cli --config config.local.json reflect-deepseek
```

没有合格证据时返回 `no_evidence`，不请求 API；有证据但没有密钥时明确失败。独立 `python -m moqi.worker --config config.local.json` 按家庭时区 03:05 之后领取当天唯一任务，`reflection.enabled` 默认关闭。任务领取记录持久保存，重启或多个进程不会重复领取。尚未实际请求 DeepSeek。

同一后台进程在 03:00 之后整理本地记忆、拟合可辨识的热模型和写入 L3 Git 日记，这部分不需要云端密钥。它重新读取运行器生成的配置；启用策略维护时，按独立冻结验证集→后续影子集→原子发布的顺序推进。缺数据、样本不足、模型资产不完整、质量无收益或退化会明确等待/拒绝；不会生成假的验收标签。后台进程的实际部署、模型与数据接入按[模型和音频准备](model-and-audio-setup.md)继续。

### 上下文、缓存与费用

日常事件与语音不会逐条请求 DeepSeek。每个家庭每天最多一次后台调用；同一份已完成计费的证据摘要不再重复发送。固定规则和 JEV 答案域放在稳定的提示前缀，变化的统计放在后面；每次只发送一次性摘要，不累加聊天历史。

`config.local.json` 的 `reflection` 参数：`monthly_budget_usd: 1`（Vincent 已确认，可调整）、`max_input_tokens: 8000`、`max_output_tokens: 2000`。输入用 UTF-8 字节数加消息开销作上界估算，选择至多 24 项证据、8 项习惯、10 项反馈；保留完整 JSON 记录，并注明省略数量。放不下的上下文返回 `context_limit`，不偷偷提高上限。普通结构化分析明确关闭思考模式。

调用前在 SQLite 原子预留**无缓存命中、达到输出上限**的估算费用。预算不足就停止云端更新，本地学习和已验证策略继续运行。成功后按实际 `prompt_tokens`、`completion_tokens`、`prompt_cache_hit_tokens`、`prompt_cache_miss_tokens` 结算；超时、重启中断或没有有效 usage 时保留预留额度，不假设失败请求免费，也不自动重试。同一数据库共享月预算，记忆回滚不重置费用账本。

查询开发者账本：

```sh
python -m moqi.cli --config config.local.json llm-cost
```

金额按 2026-10-22 官方 `deepseek-flash` 高峰价估算（每百万 token：未命中输入 $0.30、命中输入 $0.006、输出 $1.20）。其他模型尚未配置价目时不发起付费请求。这个应用内上限以记录的价目估算，服务商账单为实际费用依据；部署或价格变化时应复核价目。缓存是自动、尽力匹配的相同前缀缓存，隔夜运行不保证命中；不会为了命中率发付费的缓存预热请求，也不把本地跳过重复调用计作服务商缓存命中。

检查结果：7 项费用边界检查、6 项摘要/HTTP 检查、5 项后台任务检查通过，全部使用模拟 HTTP 和本地临时数据库；实际 API 花费与命中率待部署后记录。官方依据：[缓存机制](https://api-docs.deepseek.com/guides/kv_cache/)、[思考开关](https://api-docs.deepseek.com/guides/thinking_mode/)、[计价](https://api-docs.deepseek.com/quick_start/pricing/)。

## 语音软件与模型准备

`VoiceConversation` 接收可信唤醒会话、房间、时间和 ASR 文字；明确规则直接写入记忆，模型独有的修改通过语音确认，近期特例可以通过语音指代，不需要网页证据选择。返回的 `reply` 是交给播放层的文字，不表示声音已合成或已播放。

语音会话和未确认请求持久保存。确认在同一唤醒会话中最多等待 60 秒；跨会话或过期确认不修改旧请求。夜间没有回复，不能完成的确认/澄清不应用。已有播报策略仍需在实际音频播放前检查占用、时长和预算。

`moqi.audio` 已提供 Sherpa KWS、Silero VAD、SenseVoice、VITS TTS 和 PortAudio 适配器；`--audio-config audio.local.json --jev-model models/jev-int8` 为之后目标机的显式启用入口。麦克风线程只在唤醒会话内做 ASR；播放期间不把自己的声音再识别成指令。音频只在内存里流转，输入段、会话、队列和回复时长都有上限；不能跨 23:00 播放。播放未能发起的确认会清除待确认修改，随后一句“确认”不能误应用。

首播预留和派发状态持久保存。重启后，尚未尝试播放的缓冲可在原 60 秒时限、原房间和原额度内重新合成；已尝试但结果未知的播报不自动重播。过期或无法完成的首播会阻止该习惯后续自动执行，出现在诊断记录中；缺少必需播报也不计作用户默认接受。PCM 不因恢复而落盘，故障不会伪造成用户负样本。HA 回执 GET 在独立线程执行，不能堵住实时事件循环。

`audio.example.json`、Linux 运行/音频依赖锁、官方模型配方及清单导出工具已经提供；`moqi.assets` 检查转移后的 SHA-256。准备步骤见[模型和音频准备](model-and-audio-setup.md)。当前没有把占位路径/哈希当作资产已备齐，也未运行真实 Sherpa 或打开音频设备。构建和推理放在获授权的服务器，工控机共存性能之后验收。

JEV 的状态同样有上下文预算：按实际分词器核对其固定布局，保留完整的当前话语，只装得下的完整习惯条目；问题说明或答案超限时拒绝，不接受上游静默截断。代码能解释的请求仍不加载模型。当前只对模拟分词器和语义代理检查了该接口，真实模型资产与结果待验。

## 无硬件的软件回放

下面入口在新建隔离目录中运行，不连接 HA，不加载模型或播放音频：

```sh
python -m moqi.scenarios --directory data/software-replay-001
```

报告包含习惯形成与影子预测、两次撤销各 β+3 和 90 分钟租约、22→23°C 微调更新分布且不记为撤销、作息延后 30 分钟与版本分裂、未知归因不学习。信任和计数由行为流算出，不手工填入。温度/撤销场景中的执行回执是明确标注的协议夹具，不是实际设备操作。

2026-10-22 的隔离回放产生 3 条初始习惯、21 次影子命中，获得 L2；两次撤销的信任顺序为 L2→L2→L1，租约均为 90 分钟。温度分布从四次 22°C 增加一次 23°C，接受范围变为 22–23°C；35% 节能分位仍为 22°C，符合统计规则。漂移保留旧版本并形成 18:30 槽位的新习惯。报告的教学输入/云调用数来自实际临时数据库，网页操作为 0；这属于软件行为回放，不是家庭实测成绩。
