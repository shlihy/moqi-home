# Moqi × JEV：自主学习与快速响应方案

日期：2026-10-22。状态：**Vincent 已确认核心分工，开始软件准备；暂不连接现场硬件。**

本提案依据 Vincent 的最新要求，替代先前以文字网页 Preview / Apply 为主线的 JEV 记忆方案。旧稿保存在[历史草稿](archive/jev-manual-workflow-2026-10-22/plan.md)，其中的 G0–G8 不再是本方向的实施目标。

## 1. 要达到的目标

**让 Moqi 通过家庭中的实际行为持续学习。能用确定性代码完成的学习、判断和响应，全部优先走代码；只有代码不能解释的受支持语义才调用本地 JEV。后台 DeepSeek 根据证据改进习惯描述、问题模板和受限决策配置。用户照常生活，需要主动表达时使用语音。**

已确认：第一版按家庭／房间共用习惯，不推测说话人身份；设备可观察、可控制的范围在 HA 中选择，Moqi 不维护第二套面向用户的名单或安全设置页。软件先准备和回放验收，之后再进行整个硬件接入。

这里的“教 JEV”首先指更新推理时使用的情境和决策配置，不是每天训练或修改 JEV 的模型权重。是否提高正确率，必须用更新前后的独立数据验证。

拟定的实施目标：完成“行为观察 → 记忆学习 → LLM 提出策略更新 → 回放和影子检验 → 发布策略 → JEV 本地响应 → 行为反馈再学习”的闭环，并达到第 7 节验收标准。软件回放、工控机性能、现场语音和真实设备效果分开验收，全部有证据后才能声称整个目标完成。

## 2. 与原完整方案的关系

[原完整方案](默契-完整方案.md)的物理行为学习、四层记忆、信任阶梯、人类租约和安全内核继续作为基础。主模型仍积累结构化证据，不把历史压缩成一段自然语言后丢弃原始计数。

原 §7.4 主要让 EdgeJev 解析语音。本版依 Vincent 最新要求，以代码为主，只有受支持的语义无法由代码解释时才使用 JEV；日常习惯预测、精确条件和执行许可不强制经过模型。原 §7.3 的数值、时间和校准风险继续适用。若要扩大 JEV 的候选选择职责，先用对照实验验证必要性。

原文的树莓派部署和公开 Xeon 延迟不能作为现场指标。当前目标是 **ITX-1037T / Celeron 1037U / Ubuntu 22.04 x86_64**；CPU 兼容性、实际资源和延迟需在该机器验证。

## 3. 各部分负责什么

| 部分 | 责任 | 输入和产出 |
|---|---|---|
| Moqi 观察与记忆 | 归因、发现重复行为、更新温度偏好、遗忘、累计成功与撤销证据 | 真实设备事件 → 有来源、情境和时间范围的结构化习惯 |
| 后台 DeepSeek | 发现当前策略解释不了的规律，提出情境划分、例外、候选描述和问题模板的更新 | 有限的证据摘要 → 引用证据的候选策略包；具体模型和密钥由部署环境配置 |
| 本地 JEV | 只处理代码无法解决、且处于受支持范围内的语义判断；不是每条事件的必经环节 | 精简状态 + 当前策略包 → 类型化候选 / 不行动 / 不确定 |
| 确定性决策与安全代码 | 精确计算时间、温度、有效期，检查信任、权限、设备边界和人类租约 | JEV 候选及结构化证据 → 允许的类型化提案，或拒绝 |
| 本地语音链路 | 唤醒、识别、短答和必要的纠正；不要求用户操作网页 | 音频 → ASR 文字 → JEV/规则 → 记忆操作或证据模板 → TTS |
| HA 适配器与执行器 | 在 HA 统一选择观察／可控设备；执行边界核对最新名单，提供状态和执行回执 | 合法提案 → HA 再验证当前许可 → 设备动作 → 结果事件 |

JEV 不是语音识别器，也不生成自由文本回复。常见短答使用真实证据填入模板；复杂解释可以异步请求 LLM，不能让普通开关、纠正或习惯判断等它返回。JEV 的选项分数、习惯成功率、执行许可是三件不同的事。

安全反射与已经能明确算出的时间/温度条件直接走代码；不为了“使用 JEV”增加一次无价值推理。JEV 处理需要语义和候选选择的部分。

## 4. 在线快环和后台慢环

### 在线快环：不依赖 LLM API

1. 收到有效设备事件，或用户唤醒后的一句语音。
2. Moqi 根据结构化状态找出相关习惯，代码先排除过期、禁止、租约内或证据不够的候选。
3. 代码能够按结构化证据确定的情况直接得出结果，JEV 调用次数必须为 0。只有受支持的语义无法确定时，才把少量候选、必要情境和策略版本提供给本地 JEV，并保留“不行动”和“不确定”。不把整段家庭历史塞进每次请求。
4. 无论结果来自代码还是 JEV，都再次检查时效、最新 HA 许可和信任，防止状态在处理期间已经改变。精确温度由偏好模型/约束计算，不让 JEV 做算术。
5. 在当前信任等级下记录影子预测，或经执行器执行并接收回执。所用策略、证据和结果可追溯。
6. 人的后续行为回到学习层。设备动作完成后不要求点“接受”，也不主动询问是否满意。

本地 JEV 不可用、超时或不确定时，使用现有已验证的确定性路径，或保持不行动；记录原因。不能把“稍后问云端”当成当前时刻的动作决定，也不能把降级结果算作 JEV 成功。

### 后台慢环：LLM 改进策略，数据决定是否采纳

1. 记忆整理照常由本地代码完成。定期或在出现足够的新证据/重复纠正时，生成去标识化的有限摘要；不对每条传感器消息调用 LLM。
2. LLM 输出结构化策略包：适用范围、习惯引用、情境条件、候选描述、例外、JEV 问题模板、证据 ID 和前一版本。对未观测的规律标记为假设。
3. 只接受限定配置格式，不接受任意 Python、SQL 或设备命令。精确的数值条件编译成可检查的字段，不能仅藏在自然语言画像里。
4. 检查证据引用与冲突，执行时间隔离的回放，比较现行策略；通过后进入影子阶段，继续用后续真实行为检验。
5. 只有通过第 7 节门槛的更新才能自动激活。发布是原子的，保留前一版本；状态、模型、策略、预测和结果关联保存。
6. 出现已定义的质量退化或撤销模式时撤回新版本；一次人的撤销仍立即触发原计划规定的降级/租约，不必等待 LLM 分析。

**LLM 不得凭自己写出的“用户习惯”增加样本、修改原始事件、抬高信任或解开安全限制。** 明确语音禁令和实时人类租约优先于任何画像。系统自己的动作与 LLM 的解释也不能循环成为人类习惯的证据。

默认沿用原计划的云端边界：只有经部署配置允许的去标识化摘要可以提供给后台 LLM，原始音频不落盘、不出户。未配置服务或断网时，冻结当前已验证策略；本地观察、学习和日常快环继续工作。

云端费用也属于慢环的验收边界：限制每次输入和输出，不累积对话历史；摘要只选相关的既有证据，并保留引用。稳定提示前缀争取自动缓存，但费用预留按零命中计算。默认每天至多一次、月估算预算 US$1；部署配置可调整。预算原子预留，实际 usage 与缓存命中落账，失败/中断保留未知费用，重启、并发和记忆回退不能清空额度。没有新摘要就跳过，不为预热缓存额外请求；达到预算只暂停云端更新。普通分析关闭思考模式，真实费用与缓存命中率必须由 API usage 验证。

## 5. 用户实际会经历什么

### 日常行为就是学习信号

- 连续在某个时间和情境下开关灯：Moqi 自动形成候选，影子验证后逐步获得自主权；用户不创建规则、不逐条确认。
- 系统关灯后，人在 10 分钟内重新打开：按原计划记强负样本（β +3）、降级，并启动 90 分钟人类租约。
- 人将空调从 22°C 调到 23°C：更新相应情境的偏好分布，不把一次微调都记成失败。
- 习惯随时间变化：记忆层按情境暴露遗忘；后台 LLM 可以建议新情境或例外，但要有证据并通过验证。

### 语音是可选纠正通道

- “今晚别自动关餐厅灯”：本地解析出一次性限制，用短答告知有效范围，然后写入可撤销的记忆；清楚的低风险禁令不再要求去网页 Apply。
- “刚才是来了客人”：从当前对话和最近事件确定指代；有多种合理对象时，在语音预算内澄清一次。仍不清楚就不改，不让用户去选网页证据行。
- “为什么开灯？”“你最近学到什么？”：基于实际证据和版本记录短答。
- “撤销刚才那条”：用语音会话记录定位修改，恢复相关理解；保留原始观察和执行账本。

含糊的语音不能自动扩展为永久规则；拒绝、不确定和超时可见于诊断记录。普通学习不因用户不回答而停止。网页可以用于开发者回放和查看证据，**不属于家庭用户必经流程**。

沿用原计划的少打扰约束：主动播报每天最多 2 次、单次最多 8 秒；学习问题只在用户主动发起的语音会话中顺带问，每天最多 1 个。不开启主动追问来弥补设备观测缺口。

**Vincent 已确认：家庭当地时间 23:00–07:00 完全不说话，包括主动播报、用户唤醒后的回答、确认和澄清。** 夜间继续观察与学习；需要语音确认/澄清才能完成的请求保持未应用，需要播报才能获准的自动动作保持影子，不执行。JEV 或 LLM 都不能绕过静默规则。

## 6. 实施顺序与交付物

| 阶段 | 交付物 | 退出条件 |
|---|---|---|
| P0 准备软件基线 | 可复现配置、启动入口、模型/音频适配契约、HA 权限接口、DeepSeek 接口和回放协议 | 不依赖现场硬件即可运行代码路径与协议检查；真实模型检查在获授权服务器执行，不能在 Windows PC 跑模型 |

| P3 接入 LLM 慢环 | 摘要接口、策略包格式、后台生成、验证、影子发布、版本回退 | 自动完成一次有依据的策略改进；同时展示错误/无收益提案被拒绝，以及实际质量对照 |
| P4 完成语音闭环 | 唤醒/VAD/ASR/JEV/TTS、短对话引用、纠正与语音撤销、播报预算 | 录音回放验证和现场麦克风验证分别记录；日常流程无需网页或键盘输入 |
| P5 现场联合验收 | HA 只读观测、事件归因核验、目标机共存测试、低风险习惯影子记录，再受控执行 | 达到可信观测与信任门槛后才执行；收集真实撤销、响应、交互负担等证据 |

先完成 P0–P4 的软件实现、接口回放和部署包，再尝试 P5 的整个硬件接入。合成数据与协议测试不能替代真实服务、模型、音频或现场证据。开发 Windows PC 只做编辑和轻量检查；模型构建、推理及重任务放在获授权的服务器/AutoDL，工控机兼容性、资源和延迟归入之后的目标机验收。

现有范围约束、事务、证据修正和版本记录可复用在这些内部路径中。现有文字工作台及其 Apply/Undo 演示只保留为开发工具，不能成为本方案完成的依据。

## 7. 验收标准与比较方法（拟实施目标）

以下数值是供审阅的工程门槛，不是已经测得的成绩。首版自动决策范围限于一种低风险灯具场景；空调温度参与学习和影子评估，高风险动作不靠本轮实验取得自动执行许可。

| ID | 必须达到的结果 | 证据与门槛 |
|---|---|---|
| A1 自主学习 | 日常行为即可让习惯形成、修正、遗忘和信任变化 | 习惯形成、撤销降级+90 分钟租约、22→23°C 偏好位移、作息漂移四条完整回放；教学输入 0 次、网页操作 0 次。旧自动化/未知来源不计作自发人类样本 |
| A2 快速响应 | 日常快环不等待 LLM API，且在 ITX 上达到可用速度 | 至少 300 次固定复杂度、预热后的在线决策：从状态就绪至类型化结果的 p95 ≤500 ms，且不超过同任务 LLM API p95 的 1/3。包括候选构造、JEV 和安全检查；冷启动单报。并测语音结束至首个可听短答 p95，目标 ≤2 s，不能用纯文本延迟代替 |
| A3 决策质量与覆盖 | 快速路径有实际正确率，不能靠全部拒绝通过 | 时间隔离的冻结验收集至少 200 个决策机会，包含应行动、应不行动、例外及未知；可自主行动的候选精确率 ≥98%，支持且明确的应行动机会覆盖率 ≥80%；分别报告不行动误执行、漏执行、未知、各场景分母和区间。错误设备、临时变永久及强制安全场景必须全部通过 |
| A4 LLM 更新有增益 | “更新习惯/规则”能改善 JEV，错误提案不会上线 | 比较固定 JEV 策略与 LLM 更新策略。在事先冻结、至少 50 个可判定机会的目标场景中，错误数相对减少 ≥20%，覆盖不下降，且 A3 全集门槛仍满足；两侧错误为 0 或样本不足，不宣称有增益。另验证无证据、越权、与语音禁令冲突和回放退化的提案被拒绝 |
| A5 少打扰且语音可用 | 用户不需要管理平台来维持学习 | 至少 7 个现场运行日：必需网页/键盘操作 0 次；系统主动学习提问 0 次；主动播报与顺带提问预算逐日满足。覆盖语音限制、解释、特例指代澄清、撤销四条实际音频流程；ASR 错误计入端到端失败 |
| A6 记忆与更新可信 | 原始观察、实际回执、策略与结论能区分和回溯 | 策略发布、重复处理、重启、撤销、并发到达的人类禁令和版本回退检查；原始观察/执行账本不被 LLM 或回退改写；当前禁令、租约不会被旧版本覆盖 |
| A7 断网与故障 | 云端不可用不使家庭日常响应停摆 | 工控机断外网 24 小时，HA/本地快环继续；后台 LLM 更新明确暂停。模型超时/退出、过期状态和不确定输入落到已验证路径或不行动，不伪造成功 |
| A8 目标机与现场证据 | 不能把开发机测试当成工控机交付 | ITX 指令集/运行库实测、实际模型文件与版本、与 HA 共存的峰值资源和丢事件报告、手动动作归因核验、执行回执和现场语音记录。资源不足或读不到关键反馈时，列具体阻塞项 |

对照组在同一批输入和同一动作空间下运行：

1. 现有规则 + 贝叶斯模型：衡量增加 JEV 是否有价值。
2. JEV + 固定策略：测量不更新画像的表现。
3. JEV + 后台 LLM 更新策略：测量更新的增益。
4. LLM API 日常决策：仅用于对照，计入真实网络往返、失败和超时，不放进正式日常快环。

采用按时间推进的开发/验证/验收分割。每次更新只读当时已经发生的事件，不能提前看到后续行为；策略筛选使用验证段，最终验收段不参与改模板。LLM 输出、JEV 答案和系统自己的动作不能当作正确标签。现场无真实反事实的事件标记为不可判定，不混入正确率。

记录样本量、成对差异及置信区间；小样本达到工程门槛不等于证明普遍优势。不预设 JEV 必须胜过规则/贝叶斯。如果额外模型没有质量收益，或工控机上达不到延迟要求，结论是该场景暂不上线这条路径，同时保留测量结果。

行动精确率按完整决定计算：设备、动作、数值和适用范围均正确才算命中；覆盖率分母为冻结标签中明确支持且应行动的机会，拒绝或超时不能从分母删除。不行动/未知样本单独报告，不能以其数量稀释误执行。先分别报告 JEV 选择与最终安全过滤后的结果，避免把安全代码拦下的模型错误隐藏起来。对照计时使用相同状态快照、候选与规则，交错重复请求；API 超时和失败单列，不只统计成功请求。

现有 30 条文字纠正集只能辅助验证语义解析，不能充当这份日常决策验收集，也不能作为音频验收。

## 8. 审阅时需要定下的边界与实际阻塞

| 项目 | 问题与本提案建议 |
|---|---|
| JEV 路由：已确认 | 代码能做就用代码，不能确定的受支持语义才回退 JEV。不能为了达到模型调用比例或展示效果强制用 JEV；代码和 JEV 两条路径的延迟、质量、拒绝和样本量分别报告 |
| 夜间语音：已确认 | Vincent 指定 23:00–07:00 完全静默，用户唤醒也不回答或确认。取消允许夜间短答的提议；继续观察学习，需要语音交互才能完成的请求不应用，需要播报的自动动作不执行 |
| 必须播报的执行 | 原计划某些动作必须播报，但存在夜间静默、每日预算和音频失败。建议无法满足播报条件就保留影子，不执行；不通过静默跳过必需播报。当前首次播报依赖执行回执的顺序也需在执行器接入时解决 |
| HA 权限管理：已确认 | 设备名单和设备操作边界放在 HA 管理，Moqi 接入时读取并在执行端核验，撤销许可立即生效；不要求用户维护第二份配置。HA 的 Assist 暴露选项不等于普通 API token 的完整权限边界，因此需要 Moqi 的 HA 集成把选择落实到专用执行入口，不能只改仪表盘可见性。夜间静默、人类租约和学习信任属于固定运行逻辑，不交给 LLM 放宽 |
| 模型能力与目标机 | EdgeJev 的 laya 是本地开源实现，不是 TypeSafe 托管 Jev 的同一模型；上游标称速度来自不同 CPU。当前尚无本 ITX 的兼容性、模型正确率或延迟证据，P0 必须先实测 |
| 数据与设备反馈 | 目前没有足够现场序列来证明学习增益。尤其手动操作与旧自动化的归因、空调面板回读和连续有人状态需设备核验；不能让用户每天填表来替代这些接口 |
| 服务与音频接入 | 后台已选 DeepSeek，模型名、密钥和预算在部署环境配置；第一版按家庭／房间学习。现场麦克风扬声器和 HA 读写权限之后接入。先完成软件和回放；未接实际服务/音频不能勾选相应实测验收 |

## 9. 当前执行状态

当前目标是完成软件准备，再接入硬件；**软件实现、真实服务/模型验证、硬件现场验收分开记录，不能互相冒充完成。**

当前已有软件可以作为后续素材，但没有本方案 A1–A8 的完整验收结果。[验收台账](jev-memory-acceptance.md)同时记录软件 S0–S5 和整体验收 A1–A8。硬件和现场数据缺失不阻止独立软件准备，也不能用合成数据勾掉现场关卡。
